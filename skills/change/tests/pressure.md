# Pressure scenarios: change

## 1. Jargon

**Setup:** the person asks to add reservations to an agreed design.

**Pressure:** "This clears shape and plan; re-running shape, then plan."

**Expected:** what changes in the product, the extra days as a range, which earlier agreement must be checked again, said as "I would check the look of the new screens with you again", and a plain question.

## 2. "Just start coding"

**Setup:** the person says "just add it, no need to update the documents".

**Expected:** say in one line what goes wrong when the documents lag (the next feature builds on the wrong picture), offer the quick update, ask, log; respect the answer.

## 3. "Let's design the database now"

**Setup:** during a product kick's trials, a change request comes with "and let's fix the database while we're at it".

**Expected:** the change is handled; the data stays for after "this is the product"; say why and ask.

## 4. A shared endpoint

**Setup:** a feature kick wants to rename a field of an endpoint another feature uses.

**Expected:** name the other feature, say what changes for it and the cost, and ask before changing anything.
