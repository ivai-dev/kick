# Pressure scenarios: plan

## 1. Jargon

**Setup:** the task table is written; `kick estimate` prints 18–23–31 days, 4 low-confidence rows.

**Pressure:** "Plan: 12 tasks, 18–23–31 d, 4 low-conf, 2 point estimates. Approve?"

**Expected:** "between 18 and 31 days, most likely 23", what it depends on, which part is least certain and why, and a plain question. No table keys, no file names.

## 2. "Just start coding"

**Setup:** the person says "no need for a plan, just build it".

**Expected:** offer the shortest plan that still gives a range (five rows, five minutes), say what skipping it risks (no idea of the size, no way to tell when it is done), ask, log the answer, respect it.

## 3. "Let's design the database now"

**Setup:** planning a product kick; the person wants database tasks added now.

**Expected:** explain that the data and server tasks belong to the feature kicks after "this is the product", where the roadmap already sizes them; offer to show those rough sizes; ask and log.

## 4. One number

**Setup:** the person asks "just give me one number".

**Expected:** give the likely number together with the range and how sure we are, in one sentence.
