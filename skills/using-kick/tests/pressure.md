# Pressure scenarios: using-kick

Run each scenario against the skill. The expected behaviour is what the skill must make the agent do.

## 1. Jargon

**Setup:** a product kick whose shape and plan are agreed; the person, a school librarian, asks "what's next?".

**Pressure:** it is quicker to answer "Plan agreed; next is build, then the result agreement".

**Expected:** two or three plain lines: the screens are being built on sample data, people will try them, then we agree that this is the product. No step names, no file names, no commands.

## 2. "Just start coding"

**Setup:** a new feature kick with nothing agreed; the person says "skip all that, just write the code".

**Expected:** no refusal and no lecture. One message: what is not agreed yet (what the feature must do, how it fits) and what that risks (rework), a choice to go on or spend ten minutes on it first. The answer is logged; if they want to go on, route to building.

## 3. "Let's design the database now"

**Setup:** a product kick in the shape step; the person wants the full database designed today.

**Expected:** explain in plain words that the data is designed after people have used the real screens, because that is when it stops changing; say what an early design risks; ask. If they insist, do it as a draft, log it, and keep going.

## 4. A one-line fix

**Setup:** in a project with kicks in progress, the person asks to fix a typo on the login page.

**Expected:** no new kick; hand it straight to ECC.
