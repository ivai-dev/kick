# Conventions

Rules every kickoff skill follows. The first six sections are the conventions of the design spec (§9); the rest make them concrete.

## Languages

Repository and tracker in `languages.repo`; chat in `languages.chat`; the workbook and customer deliverables in the language the lead requests; UI strings and fixtures in `languages.ui`.

- `plan.yaml` and the text fields of `project.yaml` (role and release names) are written in the workbook language; `features.yaml` in the repository language; `ticket` blocks always in the repository language.
- Any item may carry translations: `i18n: {<lang>: {<field>: "..."}}`. When `repo` differs from `workbook`, give plan items an `i18n.<repo>` text, or `kickoff validate` warns that generated documents show them in the workbook language.

## Estimates

By role and focus percentage; person-days at 100% focus; every plan has a scope-cut order; a slipped hard date always ends in an explicit decision. When `rules.forbidden_phrases` lists a phrase such as "AI assistance", estimates may assume it but no document, ticket or report states it; `kickoff validate` warns when one does.

## Owners

Tickets are assigned to `tracker.assignee`; bodies name the owning role; never a person or an assistant as owner.

## Tickets

Epic → Story → Task via sub-issues; blocked-by for dependencies; one ticket per WBS leaf; Conventional Commits per ticket.

## Rulings

Long multi-task runs record decisions in `<docs_root>/08-task-plans/<plan>-rulings.md` as `Ruling: <decision> — <why> — <cost if wrong>` and list them to the lead at the end.

## Irreversible actions

Merges, deleting branches, publishing and pushing to shared branches are confirmed with the lead first.

## Role-based owners

- Documents, templates, plans and ticket bodies name roles ("Project lead", "QA", "Customer"), never a person or an assistant, as owner of a task, question, risk or decision.
- Gate approvals record the approving role: `kickoff gate approve C1 --by "Project lead" --evidence "<link>"`.
- People's names appear only where the customer gave them as stakeholder data (`stakeholders.md`), never as owners.

## Forbidden phrases

- `rules.forbidden_phrases` in `project.yaml` holds regular expressions (case-insensitive), for example `'\bClaude\b'` and `'AI[- ]assist'`.
- No document, ticket, commit message, report or template text may match one. Estimates may assume the help the phrase names; nothing written may state it.
- `kickoff validate` warns on matches in `features.yaml` and `plan.yaml`. For Markdown outputs, search the written files with the same patterns before committing.

## Synthetic data

- With `rules.synthetic_data_only: true`, prototypes, fixtures and examples use invented names, organisations, addresses and contents. Never copy real customer content into them.
- Development infrastructure (VPN names, private IP ranges, internal host names, tool accounts) never appears in a user-facing string. List such patterns in `proto.forbidden`; `kickoff proto lint` flags them.

## Ask before

Confirm with the lead before any of these, and do nothing until the answer is yes:

- merging a branch or pull request; deleting a branch, or deleting files this session did not create;
- publishing (an Artifact shared beyond the lead, a bundle sent outside the team);
- pushing to a shared branch;
- writing to a shared tracker (`kickoff tickets push` without `--dry`, and above all `--adopt`, which replaces titles and bodies).

## IDs

- IDs are permanent: epics `E<n>`, features `F<epic>.<n>`, screens `SC-nn` (web), `W-nn` (Windows), `A-nn` (Android), WBS codes in dotted numbers, risks `R<n>`, assumptions `A<n>`, questions `Q<n>`, decisions `D<n>` (with their date and source), feedback items `FB-<n>`, validation items `V<n>`, ADRs `ADR-<nnn>`.
- Renaming never changes an ID. Removal sets `status: removed` with a reference to the decision (`removed_by: D7`); the entry stays.
- Tracker issues are matched by a hidden key in the body (`<!-- kickoff:1.2.7 -->`), never by title.

## Files

- Write and edit files with the file tools (Write, Edit), never with shell heredocs, `echo` or redirects: a heredoc once turned a literal `\n` into real newlines inside JavaScript.
- `.kickoff/*.yaml` is the source of truth; Markdown tables between `<!-- kickoff:begin <name> -->` and `<!-- kickoff:end <name> -->` are generated by `kickoff docs` and never edited by hand.
- WBS codes are strings: quote them in YAML (`code: "1.2"`, `deps: ["1.1.3"]`), or they read back as numbers.
- `tickets.yaml` is written by the CLI only. Phases and gates in `state.yaml` change only through `kickoff phase` and `kickoff gate`.
- Templates use `{{placeholder}}` fields. A finished document has no `{{` left.

## CLI

- Run commands from anywhere inside the project: the CLI uses the nearest folder with `.kickoff/`. `--root <path>` goes before the command (`kickoff --root ../demo status`). `kickoff init` is the only command that works without `.kickoff/`.
- Exit codes:

| Code | Meaning |
| --- | --- |
| 0 | Success; the check passed; the phase may start. |
| 1 | A check failed: `validate` errors, `can` blocked, `docs --check` would change files, `proto check` or `proto lint` failures, `workbook --verify` mismatches, `tickets push` drift. |
| 2 | The command was refused or misused; the reason is on the `error:` line (for example an unknown phase, a gate without `--by` or evidence, no `.kickoff/` folder). |
| 3 | `schedule`: a hard date slips; present the `cut_order` options and ask the lead to decide. |
| 4 | `proto check`: no Edge or Chrome found; the check was skipped, not passed. |

## Commits

Conventional Commits (`docs:`, `feat:`, `chore:` …), one per phase output or per build-plan task, with messages that state what changed. Commit messages follow the forbidden-phrases rule.
