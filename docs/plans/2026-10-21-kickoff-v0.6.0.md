# Kickoff 0.6.0 "Plan, not tickets": implementation spec

- **Repository:** the plugin repository. Branch `feat/kickoff-0.6.0`. **From:** 0.5.0. **To:** 0.6.0.
- **Lead decisions (2026-10-21):**
  1. Kickoff no longer manages tickets. It keeps the prototype (FE v0), the feature set, the WBS and the estimate, and it ends at the baselined plan (C6).
  2. Actual dates pulled from a tracker are dropped. The plan is the baseline and the estimate; progress tracking belongs to the team's tracker and to ECC.
  3. The WBS is handed over as files: `kickoff export` writes CSV, JSON and Markdown that any tool can import (Jira, GitHub, Linear, an ECC session).
- **Replaces** the 0.6.0 handoff planned in the 0.4.0 spec (§13).

## 0. Rulings

| ID | Decision | Reason |
| --- | --- | --- |
| P-1 | Remove the `tickets` phase. `PHASES` ends at `plan`. When everything is done, `next_step` says: `done: plan baselined; run kickoff:feedback when customer feedback arrives; kickoff export hands the WBS over`. | Lead decision 1. |
| P-2 | Remove: `kickoff tickets plan|push|pull|link`, `tickets.py`, `tracker.py`, `tickets.schema.json`, the `kickoff:tickets` skill, the `/kickoff-sync` command, actuals in `schedule` and `docs`, and the tests and fake `gh` that served them. | Lead decisions 1 and 2. |
| P-3 | **Old files stay readable.** `state.yaml` may still hold `tickets: done` (the schema allows it; status ignores it). `project.yaml` `tracker` is optional and ignored. `.kickoff/tickets.yaml` is ignored, and `kickoff validate` warns that it can be deleted. | No migration step for existing projects. |
| P-4 | **The package `ticket` block becomes `item`:** title, type, epic, areas, desc, ac, sprint. The tracker-only fields `status` and `milestone` go. `ticket` is still read in 0.6 with a validate warning, and dropped in 0.7. The example is migrated. | The block carries the only work-item detail (acceptance criteria) that the export needs. Features carry none. |
| P-5 | **`kickoff export [--out DIR] [--format csv,json,md]`.** The default folder is `<docs_root>/06-planning/export/`; the files are `wbs.csv`, `wbs.json` and `wbs-items.md`. - One record per package: code, name, phase, group, role, effort (person-days), deps, release, prio, the feature IDs that list the package in `wbs`, the planned start and end from the baseline schedule, and the `item` fields. - Text comes in the workbook language. CSV lists are joined with `; `, and dates use ISO format. | Lead decision 3. A file is neutral across tools, and the lead imports it with the tracker's own importer. |
| P-6 | The pre-write hook no longer guards `tickets.yaml`. The ECC ownership rule loses `epic-decompose` and the tickets rows; the epic-script runner `kickoff ecc run` stays for users who want it. | Nothing in kickoff writes issues any more. |
