# Kickoff 0.7.0 "Design studio": implementation spec

- **Repository:** the plugin repository. Branch `feat/kickoff-0.7.0`. **From:** 0.6.0. **To:** 0.7.0.
- **Problem:** projects made with kickoff looked alike. `ux-design` took its direction from `ui-ux-pro-max --design-system`, a deterministic lookup by product type. Four different B2B briefs, run with kickoff's own dials (`--variance 2 --motion 2 --density 4`), gave `#2563EB` twice, `#0369A1` once and a terminal green with Fira Code for a logistics console. The FE template then defaulted to a blue primary (hue 258), Segoe UI and the stock shadcn look. The concept round was shown to the lead only, as static artboards. No reviewer asked whether a screen could belong to any other product.
- **Lead decisions (2026-10-21):**
  1. A new gate **CD, "Customer approved the design direction"**, approved by the customer before any prototype screen is built.
  2. **Anthropic `frontend-design` and `pbakaus/impeccable` are required** (checked like ECC). Emil Kowalski's skills are optional.
  3. **`ui-ux-pro-max` becomes optional:** no `--design-system`, no required per-screen brainstorm. It stays a reference for UX guidelines, charts and stack rules.
  4. **Customer co-design** happens in the published Artifact: a direction switcher and a bounded tweak panel in the prototype bar, plus Artifact comments for remote feedback.
- **Principle:** kickoff sets the quality floor (accessibility, density, Vietnamese type, data at volume, overlays, copy rules: lessons from real projects) and never the aesthetic ceiling (palette, type, shape language, motion personality, imagery, signature).

## 0. Rulings

| ID | Decision | Reason |
| --- | --- | --- |
| D-1 | **New phase `design-direction`** between `fe-foundation` and `prototype`, left through gate **CD** (approver: customer). `design-direction` needs `fe-foundation` and CF; `prototype` needs `design-direction` and CD. | Decision 1. Directions are judged on the real reference screens with seeded data, which exist only after the FE v0 foundation. |
| D-2 | **Legacy projects** (and `kickoff phase start|done` now refuse a phase that `kickoff can` blocks, so a skipped gate cannot be forged into a legacy pass): when `design-direction` is absent from `state.yaml` and `prototype` has started (any status) or `signoff`/`solution` is done, the phase and CD count as satisfied, and `kickoff status` prints `skipped (prototype started before 0.7.0)`. The 0.5.0 `fe-foundation` rule becomes one entry of the same table. | No migration step; a project in the middle of its prototype is not sent back. |
| D-3 | **CF is technical; CD is visual.** The visual-direction ADR moves from `fe-foundation` to `design-direction`. The reference screens of `fe-foundation` are built on the template's neutral tokens. | One decision per gate, each with its own approver. |
| D-4 | **`kickoff design doctor`** checks G1 `frontend-design` and G2 `impeccable` (a plugin in `installed_plugins.json`, or a skill folder in `~/.claude/skills/` or the project's `.claude/skills/`), G3 that the project turned off impeccable telemetry, and reports the optional skills (Emil Kowalski's, `ui-ux-pro-max`). G1 or G2 missing: exit 1. | Decision 2. Same shape as `kickoff ecc doctor`. |
| D-5 | **`kickoff design setup [--dry]`** writes `"telemetry": false` into `.impeccable/config.json` (merged) and impeccable's ignore block into `.gitignore`. | Impeccable's roll API never receives project content, but it records which card won unless told not to. Customer work defaults to off; the lead may turn it back on. |
| D-6 | **Impeccable owns its own files** (`PRODUCT.md`, `DESIGN.md`, `.impeccable/`), like an ECC writer. Kickoff's records stay authoritative: `design-brief.md`, `directions.md`, the direction ADR, `design-system.md`, the tokens. `PRODUCT.md` is written by `/impeccable init` from the kickoff documents; `DESIGN.md` by `/impeccable document` after the lock. | Kickoff owns; tools work. |
| D-7 | **Directions in the FE v0:** each direction is `apps/web/src/styles/directions/<id>.css`, scoped to `:root[data-direction="<id>"]` and `…[data-theme="dark"]`, imported by the project's `directions.css`. `config.ts` gains `directions: [{ id, name, summary }]` and `direction` (the locked id). Tokens derive from `--brand-h` and `--brand-c` so the tweak panel can move them. | The switcher swaps themes on the same real screens; nothing is mocked twice. |
| D-8 | **Prototype bar:** a Direction select when two or more directions are offered and none is locked; a **Tweaks** popover with brand hue, brand chroma, radius and motion, a live contrast reading of the primary button, Reset, and "Copy link" (the URL carries `?look=` and `?tweak=`). Both are reserved URL parameters. | Decision 4: the customer adjusts, and sends back a link or a comment that reproduces exactly what they saw. |
| D-9 | **`kickoff fe check`:** (a) runs impeccable's deterministic detector on `apps/web/src` and `packages/ui/src` (exit 2 = findings = failure; `--skip-detect` reports it as skipped); (b) after `design-direction` is done, fails while the manifest has no locked `direction` (the lock is `config.ts` `direction`, which the kit applies everywhere, so `tokens.css` stays the neutral base); (c) checks that every offered direction has its CSS file, imported by `directions.css`, whose dark block repeats every variable of the light block; (d) `--direction <id>` runs the sweep in that direction. | Anti-slop and anti-default become checks, not advice. |
| D-10 | **Template tokens are neutral** (brand chroma 0, system font stack), so an unlocked project looks unfinished rather than "shadcn blue". | No silent default direction. |
| D-11 | **New read-only agent `kickoff:art-director`:** distinctiveness and brand fit against `design-brief.md` and the locked direction: the "could this belong to any other product?" test, the signature present on every screen group, the AI-default clusters of `frontend-design`. It joins the concept round and the prototype design review. | Nobody judged distinctiveness before. |
| D-12 | **Skills:** new `kickoff:design-direction`; `ux-design` loses the direction steps and the concept round; `fe-foundation` loses the visual ADR; `prototype` replaces the per-screen `ui-ux-pro-max` brainstorm with the `frontend-design` two-pass plan and uses `/impeccable audit` and `/impeccable polish` before delivery; `feedback` reopens CD for direction remarks; `using-kickoff` lists the phase, the gate and `references/design-tools.md`. | Decisions 2–4. |
