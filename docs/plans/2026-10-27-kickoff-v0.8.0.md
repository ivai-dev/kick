# Kickoff 0.8.0 "Process, not stack": implementation spec

- **Repository:** the plugin repository. Branch `feat/kickoff-0.8.0`. **From:** 0.7.0. **To:** 0.8.0 (breaking).
- **Problem:** a game project run through 0.7.0 came out of `ux-design` as a web management console. Three causes:
  1. The plugin shipped one product shape: shells `app` and `site`, four business home shapes, and a "floor" of rules (one filled button, motion cap 300 ms, no weight above 700, KPI-free homes, data tables at volume) taken from two web projects. A product that is not a web app has nowhere to go.
  2. Structure was decided early, alone and unreviewed. `ux-design` had no gate and no review; the customer chose only colours at CD (the directions differed "in tokens and CSS only"); the reviewers that could catch "this is an admin site" ran after the whole prototype was built.
  3. The confirmations were blind: an Interview of one-line options, filled from template fields, with no preview and no word on what a wrong answer costs or when it would be found.
- **Lead decisions (2026-10-27):**
  1. **Remove the FE kit and the shipped design rules.** The plugin holds process and design philosophy only, so it runs for any project (web, game, mobile, desktop, service).
  2. `prototype` stays as a **process phase, tool-agnostic.** The plugin defines what it must cover and how it is reviewed; the project picks how to build it and records the choice as an ADR.
  3. **`fe-foundation` and gate CF are removed. `design-direction` becomes `design-concept`, before the full `ux-design`, and gate CD stays** with the customer: the customer chooses structure and feel, not only colour.
  4. **`frontend-design` and `impeccable` are no longer required;** `kickoff design *` is removed. They are named as optional aids for web UI.
- **Principle:** the plugin says how to decide and review a design, never what the design is. Rules are the project's own, derived from its brief, each with a reason and a test.

## 0. Rulings

| ID | Decision | Reason |
| --- | --- | --- |
| D-1 | **Phases:** `init, discovery, research, feature-map, design-concept, ux-design, prototype, signoff, solution, plan`. `fe-foundation` and `design-direction` are gone. **Gates:** `C1, C2, CD, C3, C4, C5, C6`; CF is gone. | Decision 3. |
| D-2 | **Order and requirements:** `design-concept` needs `feature-map` and C2; `ux-design` needs `design-concept` and CD; `prototype` needs `ux-design`; `signoff` and `feedback` need `prototype`; `solution` and `plan` are unchanged. CD is approved by the customer after `design-concept`. | The customer picks structure and feel before the spec is expanded, so the spec cannot bake in an unchosen shape. |
| D-3 | **State migration** (in `state.py`, applied when state is loaded, written back with the next change): `design-direction` is renamed `design-concept`; `fe-foundation` and gate CF are dropped; a project whose `ux-design` is done, has no `design-concept` and has not started `prototype` gets `ux-design` marked stale, so it is re-run after CD; a project that started `prototype` before CD existed keeps the existing legacy rule (the phase and CD count as satisfied). The state schema still accepts the old names so an unmigrated file validates. | A project mid-flow is not sent back, and none needs a manual edit. |
| D-4 | **CLI removed:** `kickoff fe` (`new`, `update`, `check`, `bundle`), `kickoff design` (`doctor`, `setup`), `fe.py`, `design.py`, `templates/fe` (the kit, `apps`, `packages`), the pre-write guard of `packages/kit`, the CI job `fe`. **CLI added:** `kickoff prototype record --artifact <link|path> [--version <n>]` (the old `fe record`, same `state.yaml` `prototype` block). | Decisions 1 and 2. A hook still refuses hand edits of `state.yaml`. |
| D-5 | **`project.yaml`:** the `fe` block becomes `design` with `ux_spec` (default `<docs_root>/05-design/ux-spec.md`) and `forbidden` (patterns that must never reach the product's user-facing text); `fe.dir` is dropped. A project that still has `fe` or `proto` is read as before, and `kickoff validate` warns to rename it. | A stack-neutral name; no project file breaks. |
| D-6 | **Screen inventory checks move into `kickoff validate`** (new `uxspec.py`, from `fe.py`'s `parse_ux_spec`): the first table whose header starts with `ID`, five columns; unique IDs; a release that exists in `project.yaml`; every `screens` ID of an active feature is in the inventory (error); an inventory screen no active feature serves (warning). Platform and role are free text: a "screen" is any unit of experience (screen, scene, level, flow state). | The one cross-check the CLI can do for every stack. |
| D-7 | **`check-docs` also applies `design.forbidden`** to the files it is given. | Replaces the code scan of `fe check`. |
| D-8 | **Skills:** `fe-foundation` is deleted; `design-direction` is renamed and rewritten as **`design-concept`**; `ux-design` loses the structural rule set and the web-shaped templates and gains a review step; `prototype` is tool-agnostic. 12 skills. `using-kickoff` loses the design-tools start-up check. | Decisions 1–4. |
| D-9 | **One philosophy file:** `skills/using-kickoff/references/design-philosophy.md`. Every design skill and review agent reads it. It replaces `foundation-rules.md`, `content-and-craft.md`, `guidance-library.md`, `data-at-volume.md`, the `design-system.md` template (a `design-rules.md` template takes its place: the project's own rules), `screen-checklist.md` and `design-tools.md`. | Decision 1: philosophy, not values. |
| D-10 | **New method "Decision card"** in `methods.md`, used by every design confirmation and by gate requests. A card states what is decided and what it locks; 2–3 options, each with what the user will see (a sketch, an example, a reference), who it serves, and the cost and the phase in which a wrong choice would surface; a recommendation with its reason; what was assumed; and always "none of these" and "show me first". | Fixes the blind confirmations. |
| D-11 | **Earlier reviews and visible rulings:** `ia-reviewer`, `viewpoint-reviewer` and `art-director` run on the concepts and on the `ux-spec` (not only on the finished prototype); `ux-design` ends with a *fit test* (a written answer to "what makes this not a different kind of product?"); rulings are listed to the lead at every task-group end and at every gate, not only at the end of a phase. | Design faults surface where they are cheap to fix. |
| D-12 | **Agents:** the five read-only agents stay; their criteria come from the brief, the project's `design-rules.md` and the philosophy file, not from shipped values. `art-director` no longer reads `frontend-design`'s list; it applies the category-default test of the philosophy. | Decision 1. |
| D-13 | **ECC manifest** (`ecc.py` `COMPONENTS`) drops the components only the removed skills used (`react-*`, `vite-patterns`, `frontend-a11y`, `make-interfaces-feel-better`, `motion-foundations`, `ui-demo`, `react-reviewer`, and `contract-first` and `accessibility` where nothing else names them). Skills may still name ECC components that stay in the manifest. | `test_every_manifest_component_is_used`. |
| D-14 | **Version 0.8.0.** Projects on the FE v0 (0.5–0.7) keep their `apps/` and `packages/` as ordinary project code: kickoff no longer owns or guards `packages/kit`. The kit and rules stay in git history under the tag `v0.7.0`. | Breaking change, stated in the CHANGELOG. |
