### 2.5 Wrapper rules (`ui.js`)

1. **Projects never render `<wa-*>`.** Only `ui.js` and `shell.js` do. Lint L5 enforces it.
2. **Controlled state stays in Preact.** Wrappers set `el.open = !!open` in an effect and listen to library events **on
   the host only** (`e.target === el`), because `wa-hide` from a nested dropdown or tooltip bubbles. Helper:
   `useOwnEvent(ref, name, fn)`.
3. **Keep mounted.** Overlays render always and take `open`; the library plays the exit and returns focus. A wrapper
   rendered with `open=false` from the start renders the host with `open` unset (cheap).
4. **Close requests.** On `wa-hide` from the host: if the surface is an alert (ConfirmDialog) and `e.detail.source ===
   el` (backdrop click), `preventDefault()`; if `dirty` is true, `preventDefault()` and open the "Bỏ thay đổi?"
   ConfirmDialog (class F); otherwise call `onClose()`.
5. **Initial focus** via `autofocus` on the target element (first field; "Hủy" in ConfirmDialog; the heading with
   `tabindex="-1"` for passive dialogs). Never the × button.
6. **Return focus.** The library returns focus to the invoker; when the invoker no longer exists (a menu item that
   opened a panel), the wrapper stores the menu trigger as `returnTo` and focuses it on `wa-after-hide`; if that is gone
   too, the page `h1`.
7. **Back closes the top overlay.** On open, `KIT.overlays.push({ id, close })` (from `logic.js` stack) and
   `history.pushState({ kitOverlay: id }, "")`; `popstate` with a lower state closes the top entry; closing by other
   means calls `history.back()` only if the top history state is that overlay's.
8. **Esc** is the library's (top layer handles stacking). Kit-native popups (Combobox listbox, DateField grid, legacy
   Menu) register in the same `KIT.overlays` stack and handle Esc only when they are the top entry.
9. **Scroll lock and gutter.** Modal library dialogs lock the page; kit CSS sets `scrollbar-gutter: stable` on
   `#kit-content, .content, .site-scroll, .m-content, .bare-scroll` so nothing shifts.
10. **Density inside overlays** comes from `<html data-density>` (K-2), because the top layer still inherits from the
    DOM ancestors and the root.

### 2.7 ConfirmDialog alertdialog patch

`wa-dialog` renders `role="dialog"` with `aria-label` only. In `ConfirmDialog`, after `await el.updateComplete` and on
every change of `consequence`:

```js
const d = el.shadowRoot && el.shadowRoot.querySelector('[part~="dialog"]');
if (d) { d.setAttribute("role", "alertdialog"); d.setAttribute("aria-description", consequence); }
```

`aria-describedby` cannot cross the shadow boundary, so `aria-description` carries the consequence (verified in r6
T17). Selftest S5 asserts the role and a non-empty description; re-run on every library upgrade.

## 4. Density modes API

| Piece | Contract |
| --- | --- |
| Config | `KIT_CONFIG.density = { app: "compact", site: "comfortable", phone: "touch", windows: "compact" }` (these are the defaults); `roles[].density` overrides per role; `KIT.register(id, { density })` overrides per screen (rare). |
| Resolution | `KIT.logic.resolveDensity({ shell, layout, narrow, coarse, roleDensity, screenDensity, user })` returns one of `compact`, `comfortable`, `touch`, `kiosk`. Order: frame (`kiosk` frames set their own attribute) → screen → user override (app shell only) → `touch` when `layout` is `phone-native` or `phone-frame`, or `narrow`, or (`coarse` and shell is `site`) → role → config default for the shell. |
| User override | `A.setDensity("compact" \| "comfortable" \| null)`, stored with `KIT.util.store` as `density-<role>`; exposed in the ProtoBar as a segmented control "Mật độ: Gọn · Thoải mái" (strings `proto.density`, `density.compact`, `density.comfortable`; en "Density: Compact · Comfortable") shown only for app-shell roles. |
| Attribute | `main.js` stamps `data-density` on `<html>`; shells repeat it on `.shell`, `.site`, `.m-app`, `.bare-page` (the resolved value); frames set their own on the frame screen. |
| Context | `useApp().density`, `useApp().wc`, `useApp().coarse`. |
| Window classes | `KIT.logic.windowClass(width)` → `compact` (< 600) · `medium` (< 840) · `expanded` (< 1200) · `large` (< 1600) · `xlarge`; stamped as `<html data-wc>`; updated on resize (rAF-throttled). |
| Scope helper | `KIT.ui.DensityScope({ mode, children })` renders `<div data-density=${mode} class="kit-scope">` with `display: contents`. |
| Pointer | `matchMedia("(pointer: coarse)")` with a change listener. |

## 6. Motion API

### 6.1 One navigation commit point (`main.js`)

Every state change that changes `screen` or the `params` of the same screen goes through `commitNav(patch, dir)`:
`go` → `forward` (or `lateral` when the target is a nav item of the current role: `reg.nav` set), `back` → `back`,
`jump`, `onHash`, `setRole`, `setPlatform`, `openPicker` → `lateral`.

```js
function commitNav(patch, dir) {
  const el = document.getElementById("kit-content");
  const leave = el ? el.scrollTop : 0;
  const from = document.activeElement && document.activeElement.closest("[data-kit-key]");
  const run = () => set((s) => ({ ...(typeof patch === "function" ? patch(s) : patch), _dir: dir, _leave: leave,
    _from: from ? from.getAttribute("data-kit-key") : null }));
  if (api._vt) api._vt.skipTransition();                       // M8: interruptible
  if (!document.startViewTransition || KIT.util.reduced() || !root.dataset.ready) { run(); return; }
  root.dataset.nav = dir;
  const vt = document.startViewTransition(() => new Promise((res) => { run(); setTimeout(res, 0); }));
  api._vt = vt;
  vt.finished.finally(() => { if (api._vt === vt) { delete root.dataset.nav; api._vt = null; } });
}
```

`pushHist` stores `{ screen, params, platform, scroll: leave, from }` (the `_leave` and `_from` captured by
`commitNav`). `back()` pops the entry and sets `_restore: entry.scroll` and `_from: entry.from`, so the screen returns to
its scroll position and focuses its opener. `A.go(id, params, { replace })`: `replace`
updates params without a history entry and without a transition (filters, tabs, paging). `data-kit-key` is an
optional attribute projects put on openers (row links, cards) so Back can return focus to them.

### 6.2 Scroll, focus and title (`shell.js` `ScreenBody`, every shell)

```js
useLayoutEffect(() => {
  const sc = document.getElementById("kit-content");
```

`app.screenTitle`: vi "{screen} · {product}", en "{screen} · {product}". The site-only scroll reset is removed. The

### 6.4 Overlay exits and `usePresence`

Library overlays animate out by themselves when kept mounted (§2.5). Kit-native surfaces (Combobox listbox, DateField
popover content, legacy Menu, the toast stack's FLIP, project panels) use:

```js
function usePresence(open, exitMs) {                // "open" | "closing" | "closed"
  const [state, setState] = useState(open ? "open" : "closed");
  useEffect(() => {
    if (open) { setState("open"); return undefined; }
    if (state === "closed") return undefined;
    if (KIT.util.reduced()) { setState("closed"); return undefined; }
    setState("closing");
    const t = setTimeout(() => setState("closed"), exitMs);
    return () => clearTimeout(t);
  }, [open]);
  return state;                                      // render while !== "closed"; data-state on the root
}
```

CSS: `[data-state="closing"] { animation: kit-out var(--dur-2) var(--ease-exit) forwards; pointer-events: none; }`.

### 6.5 Helpers (`core.js` util, logic in `logic.js`)

- `KIT.util.motion()` → `{ d1…d5, shift1, shift2 }` in ms/px read from `getComputedStyle(document.documentElement)` (one
  source with CSS).
- `KIT.util.flip(container, mutate, ms = motion().d3)`: records `getBoundingClientRect()` of `container.children` keyed
  by `data-key`, awaits `mutate()` (returns a promise resolved after render: `KIT.util.afterRender()` = two rAFs), then
  animates each moved child `translate(dx, dy) → none` with `--ease-standard` via `el.animate`; new children fade in;
  no-op under reduced motion.
- `KIT.util.collapseOut(el, ms)`: takes a leaving row out of the flow (`position: absolute` at its rect, `width` fixed),
  fades it over `--dur-2`, removes it; used together with `flip` for P4.
- `Reveal`: `.reveal { display: grid; grid-template-rows: 0fr; transition: grid-template-rows var(--dur-4)
  var(--ease-standard); } .reveal[data-open="true"] { grid-template-rows: 1fr; } .reveal > * { min-height: 0; overflow:
  hidden; }`.
- Number cross-fade: `KIT.ui.Num({ value, format })` keys the value and fades over `--dur-2`, width reserved via
  `min-width: <n>ch` from the longest formatted value seen.
- Theme switch: `main.js` adds `data-theme-switching` to `<html>` for one frame (`*, *::before, *::after { transition:
  none !important }`) around the change (P21).

### 6.6 Reduced motion

Replace the global kill-switch (`* { animation-duration: 1ms … }`) with the token block of §3.2 plus:

```css
@media (prefers-reduced-motion: reduce) {
  .ch-anim *, [data-loop] { animation: none !important; }

  ::view-transition-old(root), ::view-transition-new(root) { animation-duration: 100ms; }
  @keyframes kit-vt-in { from { opacity: 0; } }
  html { scroll-behavior: auto; }
}
```

Projects mark looping decorations (the SC-19 waves) with `data-loop`.
