# Kickoff 0.5.0 "FE foundation": implementation spec

- **Repository:** the plugin repository. Branch `feat/kickoff-0.5.0`. Merges, pushes and tags are confirmed with the lead first.
- **From:** 0.4.1. **To:** 0.5.0.
- **Lead decisions (2026-10-21):**
  1. One official stack: React + TypeScript + Vite SPA, Tailwind v4, shadcn/ui (Radix), TanStack Router/Query/Table, React Hook Form + zod, Motion, Lucide, Recharts, i18next.
  2. The frontend is a pnpm monorepo in the **same repository** as `.kickoff/` and `docs/` (`apps/`, `packages/`).
  3. The customer sees a **single-file static build published as a private Artifact**. Artifact comments keep flowing into `kickoff:feedback`.
  4. The HTML prototype kit is **removed** in 0.5.0, with no lite mode. Projects built on the kit stay on 0.4.x or migrate.
- **Defaults taken here:**
  - the frontend foundation gate is approved by the project lead;
  - mobile native is out of scope, the frontend is web and PWA only.
- **Why:** the kit grew with every project and was thrown away. FE v0 is production UI code; only its data layer is a mock, which `solution` and the build replace with the real API.

## 0. Rulings

| ID | Decision | Reason |
| --- | --- | --- |
| F-1 | **New phase `fe-foundation`** between `ux-design` and `prototype`, with a **new gate CF** ("Frontend foundation approved", approver: project lead). `prototype` requires `fe-foundation` done and CF. | The stack, style and frontend features are decided once, with evidence, before screens are built. CF makes that decision visible and reopenable. |
| F-2 | **The phase id stays `prototype`;** its content becomes FE v0 screens. The `state.yaml` key `prototype: {artifact, version}` stays. | No migration of existing `state.yaml` files. "Prototype" is still the word the customer hears. |
| F-3 | **Core principle, amended:** the **presentation stack** (frontend framework, UI and CSS libraries, frontend tooling) is decided in `fe-foundation` and recorded as ADRs with status *Accepted*. Backend, database, system architecture, hosting and integrations stay locked until C3 and C4. | Only the presentation layer moves earlier. The feature set is still signed off before the system is designed. |
| F-4 | **Owned vs copied code:** - `packages/kit` (`@kickoff/kit`) is plugin-owned: router, shells, demo bar, `Rel`, `Placeholder`, the e2e sweep, the manifest script and the ESLint rules. `kickoff fe update` replaces it; the pre-write hook refuses edits to it. - Everything else (`apps/web`, `packages/ui`, `packages/mocks`) is project-owned after `kickoff fe new`. | Same split as the kit core and project files of 0.3, now on real packages. No private npm registry is needed. |
| F-5 | **Generated files:** `kickoff fe new` writes `apps/web/src/kickoff/{config,screens,scenarios}.ts` and one stub `apps/web/src/screens/<id>.tsx` per ux-spec row. The formats are fixed (§3) so the CLI and the e2e sweep can read them. | The ux-spec inventory stays the source of truth for screens, and coverage is checkable. |
| F-6 | **Routes** are `#/<role>/<screen-id>?<params>` with hash history. Device views, records and flow steps are search params. | Every view opens from a link; a static file and an Artifact need no server routing. |
| F-7 | **Checks:** `kickoff fe check` runs, from the frontend root, `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` and `pnpm e2e`, then compares `pnpm manifest` with the ux-spec inventory (coverage both ways). - The e2e sweep covers every screen × role × {1440, 390} × {light, dark}: no console errors, one `h1`, no horizontal scroll at 390, no serious or critical axe violation. - Exit 0 passes, 1 fails. Exit 4 means pnpm or a browser is missing: the check was skipped, not passed. | Replaces `proto check` and `proto lint` with the stack's own tools plus the kickoff sweep. |
| F-8 | **Customer build:** `kickoff fe bundle` runs `pnpm build:artifact` (vite-plugin-singlefile) and prints the path of the one-file `apps/web/dist-artifact/index.html`. It is published as a private Artifact and recorded with `kickoff fe record --artifact <link>`. | A single file has no relative-path or module-loading risk in the Artifact sandbox. |
| F-9 | **Versions:** the template pins majors with caret ranges and ships `pnpm-lock.yaml`. `pnpm-workspace.yaml` sets `minimumReleaseAge: 20160` (14 days), so every resolved version is at least two weeks old. TypeScript stays `~5.9` (typescript-eslint needs `<6.1`); TanStack Table stays v8. | Reproducible installs, and no day-old releases. |
| F-10 | **Removed:** `proto new/update/check/lint/bundle/record`, `proto.py`, the kit under `cli/src/kickoff/kit/`, and the `proto` tests. `kickoff proto record` moves to `kickoff fe record`. The `proto` block in `project.yaml` stays readable for one release: `ux_spec` and `forbidden` are used when `fe` does not set them. | Lead decision 4. |
| F-11 | **ECC:** `fe-foundation` and `prototype` use the ECC frontend skills `ecc:react-patterns`, `ecc:vite-patterns`, `ecc:frontend-a11y`, `ecc:make-interfaces-feel-better`, `ecc:motion-foundations`, `ecc:react-testing` and `ecc:contract-first`. `ecc:react-reviewer` (read-only) reviews each screen group. `ecc:ui-demo` records scenario walkthrough videos for the workshop on request. | Lead decision from 0.4: delegate the work, keep the gates. |

## 1. Phases and gates

`PHASES`: init, discovery, research, feature-map, ux-design, **fe-foundation**, prototype, signoff, solution, plan, tickets.

`REQUIRES`:
- `fe-foundation`: `ux-design` done and C2;
- `prototype`: `fe-foundation` done and CF.

`GATES` gains `CF: "Frontend foundation approved"` after `fe-foundation`. The `state.yaml` schema gains the phase and the gate. Reopening C3 marks `fe-foundation` stale only if it was done after `signoff`, which it never is, so feedback does not reopen CF. A stack change is a new CF: reopen CF.

## 2. `project.yaml`

```yaml
fe:
  dir: "."            # frontend root (where package.json and pnpm-workspace.yaml live), relative to the repo
  ux_spec: docs/05-design/ux-spec.md
  forbidden: []       # text that must not appear in apps/ and packages/ (development infrastructure names)
```

All keys are optional, with the defaults shown (`ux_spec` derives from `docs_root`). The app is always `apps/web` under `fe.dir`: the template's lockfile and manifest script name it (review fix; a configurable `fe.app` was dropped).

## 3. Generated file formats

- `config.ts`: `export const config: KickoffConfig = { product, lang, locale, releases, defaultRole, roles: [{ id, name, shell: "app" | "site", home, density? }] };`
- `screens.ts`: `export const screens: ScreenDef[] = [` one object per line `{ id, code, name, roles, platforms, rel, nav, page }` `];`
- `scenarios.ts`: `export const scenarios: Scenario[] = [];`
- `screens/<id>.tsx`: `import { Placeholder } from "@kickoff/kit"; export default function Screen() { return <Placeholder />; }`

The exact formats live in the template under `cli/src/kickoff/templates/fe/` and in `fe.py`.

## 4. CLI

| Command | Does |
| --- | --- |
| `kickoff fe new [--force]` | Copies the template into `fe.dir` and appends `.gitignore.kickoff` to `.gitignore`. Writes the generated files from the ux-spec and `project.yaml` (roles, releases, `languages.ui` → `lang`/`locale`). Refuses when `apps/web` exists, unless `--force`; `--force` never overwrites project-owned files that already exist except the generated ones. Prints `next: pnpm install, then kickoff fe check`. |
| `kickoff fe update [--dry]` | Replaces `packages/kit` with the plugin's copy and prints `migration:` notes from the template's `MIGRATION.md`. |
| `kickoff fe check [--skip-e2e]` | §0 F-7. `--skip-e2e` is for quick work inside a task and never counts as the task's verification. |
| `kickoff fe bundle` | §0 F-8. |
| `kickoff fe record --artifact <link> [--version <n>]` | Former `proto record`. |

The pre-write hook guards `packages/kit/**` (F-4), in place of the kit core.

## 5. Skills

- **New `kickoff:fe-foundation`:**
  1. *Option decisions* with the lead, one at a time, each recorded as an ADR *Accepted*: the style direction (from the ux-design concept round), the platform (SPA; SSR only with a written reason, which is a 0.6 matter), the frontend features (i18n languages, density modes, data-at-volume patterns, auth shape as a mock, file upload, charts, offline or PWA), and the libraries (the official stack; any addition needs a reason). ECC: `ecc:search-first` for library choices and `ecc:council` for close calls.
  2. `kickoff fe new`, `pnpm install`.
  3. Tokens from `design-system.md` into `apps/web/src/styles/tokens.css`.
  4. A shell per role in the generated config.
  5. The mock contract per entity in `packages/mocks` (`ecc:contract-first`).
  6. 2–3 reference screens built for real.
  7. `kickoff fe check`.
  8. Ask the lead for CF.
- **`kickoff:prototype`** (rewritten): builds every screen of the ux-spec in `apps/web` on `@app/ui` and `@app/mocks`, reference patterns first, per screen group, each task verified with `kickoff fe check`. Then: design review with the `kickoff:` agents and `ecc:react-reviewer`, `kickoff fe bundle`, publish, `kickoff fe record`. The fidelity rule, the per-screen `ui-ux-pro-max` brainstorm and the data-at-volume audit stay.
- **`ux-design`:** the design-system template uses the CSS variable names of `tokens.css`. The foundation rules keep the design guidance (density, type roles, overlays, motion) and map each mechanism to `@app/ui` and `@kickoff/kit` in place of `KIT.ui`.
- **Other skills:**
  - `using-kickoff`: phase table, hard gate (F-3), red flags;
  - `feedback`: prototype step: FE v0, `fe check`, `fe record`;
  - `signoff`: demo script links are `#/<role>/<screen>?scenario=<id>`;
  - `solution`: FE ADRs are already *Accepted*; the mock contract feeds the API design;
  - `init`: AGENTS.md repository map gains `apps/` and `packages/`.
- **Lessons:** rows about kit mechanics keep their lesson but point to the new check that carries it (sweep, ESLint rule, `Rel`, routes).

## 6. Tests and CI

- **Python:**
  - `test_fe.py`: ux-spec parsing (moved), generation of the four files (exact text), `--force` rules, update replacing `packages/kit` only, coverage diff, the check orchestration with subprocess mocked (exit codes 0, 1, 4), bundle path, record;
  - `test_state.py`: the new phase and gate;
  - `test_hook.py`: the `packages/kit` guard;
  - the `test_skills.py` count becomes 13.
- **CI job `fe` (ubuntu):** copy `examples/mini` into a temp folder, `kickoff fe new`, `pnpm install --frozen-lockfile`, `npx playwright install --with-deps chromium`, `PW_CHANNEL=chromium kickoff fe check`. The `kit` job is removed. The `examples` job drops `proto lint` and `proto check`.
- **Package check:** the wheel contains `kickoff/templates/fe/package.json` and `kickoff/templates/fe/packages/kit/package.json`.

## 7. Out of scope

SSR or Next.js, mobile native, a hosted preview deploy, a private npm registry for `@kickoff/kit`, ticket handoff to `orch-*` (0.6.0).
