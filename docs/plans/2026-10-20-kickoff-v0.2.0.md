# kickoff v0.2.0 — prototype fidelity and design review

- **Date:** 2026-10-20
- **Source:** lessons from running the plugin on a real project (a public employment portal with job seekers, employers,
  staff and commune kiosks; Vietnamese UI): two design-concept rounds, a copy review, a declutter review, a five-viewpoint
  cross-review of the prototype, and the project lead's rule that "the prototype must show the real product, or the
  customer's feedback has no value".

## Problems seen

| # | Problem | Cause |
| --- | --- | --- |
| P1 | Public pages of the product use a top navigation, but the prototype could only show the kit sidebar; the team wrote "the prototype differs from the product" | The kit had one desktop shell |
| P2 | Kiosk (and other device) views of a web screen could not be opened from a link, screenshotted or checked | Hash routes carried no parameters |
| P3 | "No change", "No data yet", "Nothing here yet.", "Close", "More information" … appeared in a Vietnamese product UI; the prototype bar spoke English to a Vietnamese customer | Kit strings were English only |
| P4 | "+7.1%" next to "2.304" | `config.locale` defaulted to en-US and `proto new` did not set it |
| P5 | Small uppercase labels ("HẠN NỘP") crowd stacked Vietnamese diacritics | `.t-cap` and table headers were always uppercase |
| P6 | A kit improvement could not reach an existing prototype without `proto new --force`, which overwrites project files | No update command |
| P7 | Screen codes, look-alike KPI rows on every home, text explaining system mechanics, unclear next actions | The ux-design and prototype skills had no content, declutter or per-role home guidance, and no structured design review |
| P8 | Republishing an Artifact from a new session was refused | No lesson on verifying published files against git |

## Changes

### Kit (`cli/src/kickoff/kit/prototype`)

1. **Route parameters.** `#<screen>[-tokens][?key=value&…]`; values that look like integers become numbers, `true`/`false`
   booleans. `formatHash` writes them back. Deep links, the screen index and `proto check` routes keep them.
2. **Site shell.** A role with `shell: "site"` in `KIT_CONFIG.roles` gets the public-site layout instead of the app shell:
   a header (brand, organisation line, top menu, account area), the page, a footer, and on phones a compact header with a
   menu sheet and an optional bottom tab bar (`tabs: [screen ids]` on the role). Configuration:
   `KIT_CONFIG.site = { org, account: "<nav label of the account menu>", signIn: [{ label, go }], footer: ["…"] }`.
   Top menu items are the screens with `nav` outside the account group; `menu` on a screen overrides its label.
   A project may replace the default header or footer with `KIT.site.Header` / `KIT.site.Footer` components.
3. **Bare screens.** `KIT.register(id, { bare })`, where `bare` is `true` or `(params, role) => boolean`: the screen renders on
   the stage without any shell (device frames such as a kiosk, a full-screen start screen).
4. **Kit strings.** `KIT.t(key, vars)` with an `en` and a `vi` pack, chosen from `KIT_CONFIG.lang` or the locale; projects may
   override single strings with `KIT_CONFIG.strings`. Every kit string, in the product area and in the prototype chrome, goes
   through it.
5. **Letter case token.** `--cap-case` (default `uppercase`) drives `.t-cap` and table headers; `proto new` sets `none` for
   languages with stacked diacritics (vi).
6. **`Button` keeps its classes** when a screen passes `class`/`cls`.

### CLI

1. `kickoff proto update` — copies the kit core files over the project's copies and refreshes `index.html` outside the title,
   tokens and modules blocks; never touches project modules; prints what changed (`--dry` lists only).
2. `kickoff proto new` writes `locale`, `lang` and `shell: "app"` into `config.js` from `languages.ui`, and `--cap-case: none`
   for vi.
3. `kickoff proto check` accepts routes with role tokens and parameters (`sc-08-guest?kiosk=1&id=tt03`) and writes a narrow
   (390 px) screenshot next to the light and dark ones when `--shots` is given.
4. `kickoff proto lint` fails when `languages.ui` is not English and `config.js` sets no `locale`.

### Skills and references

1. `ux-design`: per-role shell (site or app) and home shape in Roles and IA; anti-flooding principles; a concept round with
   options on a design canvas before the design system; a copy and content review (voice, term table "one name per thing",
   only what the user needs now); craft rules (number, date and unit formats, letter case, type scale per surface).
   New references: `references/content-and-craft.md`, `references/guidance-library.md`.
2. `prototype`: fidelity rule (the prototype shows what the product shows; extend the kit instead of writing a difference
   note), site shell, bare screens, route parameters, `proto update`; the design review loop (viewpoint reviewers, cross-review,
   integrator, decisions for the lead, work packages split by file) in `references/design-review.md`; republish lesson.
3. `using-kickoff/references/lessons.md`: new rows. README: CLI table, kit features, changelog.
